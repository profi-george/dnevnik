# Спецификация: Дневник ведения

## 1. Что это и для кого
Веб-инструмент для специалиста по контекстной рекламе (Яндекс Директ), который ведёт несколько сайтов/клиентов. Заменяет ручную таблицу «Дневник» в Google Sheets: дисциплинирует фиксацию каждой правки в рекламных кампаниях и не даёт забыть проверить её последствия.

Главное действие: **зафиксировать правку в кампании и не забыть вернуться проверить результат** — приложение само напоминает, когда пора снимать показатели (через сутки, неделю и месяц после правки), и хранит прямую ссылку на отчёт, чтобы не пересобирать его заново.

## 2. User stories

- [ядро] Как специалист, я хочу завести проект (сайт/клиента), чтобы группировать по нему все действия.
- [ядро] Как специалист, я хочу зафиксировать действие (когда, в какой кампании/группе, что именно сделал, ссылка на отчёт), чтобы у меня был точный след каждой правки.
- [ядро] Как специалист, я хочу, чтобы для каждого действия автоматически создавались три контрольные точки — через сутки, через неделю, через месяц, — чтобы не проверять результат только один раз и не забыть про долгосрочный эффект.
- [ядро] Как специалист, я хочу видеть полный дневник всех действий по всем проектам, отсортированный от новых к старым, с фильтром по проекту и по периоду, чтобы ориентироваться в истории правок.
- [ядро] Как специалист, я хочу видеть список «снять сегодня» — все контрольные точки, у которых плановая дата уже наступила, а результат ещё не вписан, — чтобы ничего не пропустить.
- [ядро] Как специалист, я хочу кликнуть по ссылке на отчёт прямо из списка «снять сегодня», сразу увидеть цифры и вписать результат по контрольной точке, отметив её снятой.
- Как специалист, я хочу, чтобы поле «место действия» подсказывало ранее введённые названия кампаний/групп по этому проекту, чтобы не печатать их заново.

## 3. Модель данных

### Проект
- название (текст, например «Сайт клиента N»)

### Действие
- проект (связь на Проект)
- дата действия (дата)
- место действия (текст — номер кампании/группы или URL; при вводе подсказываются ранее использованные значения по этому проекту)
- суть действия (текст — что именно изменено)
- обоснование (текст, необязательно — почему сделали именно так)
- примечание (текст, необязательно — свободная заметка)
- ссылка на отчёт (текст-URL, необязательно)

### Контрольная точка (Снятие результата)
- действие (связь на Действие)
- тип (выбор: сутки / неделя / месяц)
- плановая дата (дата; рассчитывается автоматически = дата действия + 1 / +7 / +30 дней)
- статус (выбор: ожидает / снято / просрочено — просрочено, если плановая дата в прошлом, а статус всё ещё «ожидает»)
- результат (текст, заполняется в момент снятия)

Связи: у одного Проекта много Действий. У одного Действия ровно 3 Контрольные точки (создаются автоматически при сохранении действия).

## 4. Экраны

- **Дневник** — главный экран. Список всех действий по всем проектам (или отфильтрованных по одному), от новых к старым. У каждого действия видно 3 контрольные точки и их статус (ожидает/снято/просрочено). Фильтры: по проекту, по периоду даты действия. Кнопка «добавить действие».
- **Снять сегодня** — отфильтрованный список контрольных точек, у которых плановая дата ≤ сегодня и статус «ожидает» (по всем проектам, можно сузить по проекту). По каждой строке: ссылка на отчёт (открывается в новой вкладке), поле «вписать результат», кнопка «отметить снятым».
- **Проекты** — список проектов, добавление/переименование/удаление.
- **Форма добавления действия** — проект, дата действия (по умолчанию сегодня), место действия (с автоподсказкой по истории проекта), суть действия, ссылка на отчёт. При сохранении автоматически создаются 3 контрольные точки.

## 5. Стек и условия
- Платформа: веб-приложение
- Авторизация: нет, один пользователь без ролей и без поля «исполнитель»
- Хранение данных: SQLite (через Prisma)
- Рекомендованный стек: Next.js + Prisma + SQLite

## 6. Этапы (MVP по шагам)

**Этап 1 — скелет (показать завтра):**
- Проекты: создание/редактирование/удаление
- Добавление действия (с автоподсказкой места действия по истории проекта) + автосоздание 3 контрольных точек
- Экран «Дневник» с фильтром по проекту и периоду
- Экран «Снять сегодня»: список просроченных/сегодняшних контрольных точек, вписать результат, отметить снятой

Сквозное действие: завёл проект → добавил действие → увидел его в дневнике с 3 запланированными контрольными точками → контрольная точка «сутки» попала в «Снять сегодня» → перешёл по ссылке на отчёт → вписал результат → отметил снятой.

**Этап 2:** Бэклог гипотез (отложенные идеи, которые нельзя внедрить сразу); встроенный справочник сокращений (устройства, стратегии, атрибуции, инструменты, юнит-экономика, цвета) с быстрой вставкой в поле «суть действия»; фильтр «текст содержит/не содержит» в Дневнике.

**Этап 3:** Фильтр по конкретному месту действия (кампании/группе); статистика по накопленным действиям и результатам.

**Этап 4 (далее):** автоматическая интеграция с API Яндекс.Директа и Яндекс.Метрики (подтягивание цифр без ручного захода в отчёт); уведомления о просроченных снятиях; командная работа с ролями/исполнителями; экспорт данных.
